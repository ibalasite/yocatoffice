## 1. 願景

把一間電商公司的日常，做成一個會自己「活著」的 2.5D 辦公室。玩家像經營模擬遊戲（類 Game Dev Tycoon / 開羅遊戲）的老闆，俯視整間辦公室：五大部門的員工各自有個性、會走到茶水間聊天、回工位辦公、開會討論、對老闆公告有反應。所有行為不是腳本寫死，而是**本地 LLM 即時生成**的決策與對話。

美術風格：參考使用者提供的 2.5D 等角、明亮多彩、Q 版可愛風（Monster/竹笋 海報風格）。

## 2. 核心玩法規格

### 玩家的四個動作（唯一權力）

2. **解職（Fire）**：移除某角色。
3. **派任務（Assign Task）**：對某人/某部門下任務；角色依個性與能力去執行、回報。
4. **貼老闆公告（Announcement）**：全公司廣播一段文字；角色們會各自解讀並產生反應。
5.（互動）**與角色對話**：點某角色聊天，走本地 LLM。

### 部門（5 大類 + 老闆）
| 代號 | 部門 | 職責（電商情境） |
|---|---|---|
| 產 | 產品 | 選品、商品企劃、上架 |
| 銷 | 銷售／業務 | 開發客戶、下單、業績 |
| 人 | 人力資源 | 招募、考核、員工關懷 |
| 發 | 研發 | 系統開發、技術架構、工程實作 |
| 財 | 財務 | 帳務、預算、報表 |
| — | **老闆（Boss）** | 玩家視角；也可有一個 NPC 高管代理人 |

### 角色模型（每個 NPC）
- 狀態：精力、心情、目前任務、所在位置（工位/會議室/茶水間）。
- 大腦：個性檔 + 當前情境 → 組 prompt → call 本地 LLM → 得到「下一步行為 + 台詞」。

### 7×24 作息（世界 tick）
- 後端有一個世界時鐘（可加速，如 1 現實分鐘 = 遊戲 10 分鐘）。
- 時段驅動行為：上班/開會/午休/下班/加班；夜間與週末表現不同。
- 事件系統：訂單尖峰、客訴、系統當機、發薪日等，觸發部門協作。

## 4. 本地資源地圖（★★★ 全部現成，嚴禁重新下載 ★★★）

### 4.1 硬體 / OS
- **RTX 5090 Laptop GPU，24GB VRAM**（Blackwell sm_120）。Windows 端常駐占用 ~6–8GB，WSL 內可用 ~15–16GB。
- Windows 11 + **WSL2 Ubuntu 24.04**（發行版名稱：`Ubuntu`）。
- **WSL root 免密碼**：`wsl -d Ubuntu -u root -- <cmd>`（忘記 sudo 密碼也能裝系統套件）。

### 4.2 本地 LLM（角色大腦）— vLLM
- 環境：WSL 內 `~/vllm-test/.venv`（Python 3.12，vLLM 0.32.0，torch 2.13+cu130）。
- 模型：**`Qwen/Qwen2.5-7B-Instruct-AWQ` @ 64K context（YaRN）**。
  - 64K 怎麼來：7B 原生只有 32K，用 **YaRN rope scaling（factor 2.0）**延伸到 64K。
- **端點：`http://localhost:8000/v1`**（OpenAI 相容；Windows、WSL 皆可連）。
  ```bash
  VLLM_USE_FLASHINFER_SAMPLER=0 VLLM_ATTENTION_BACKEND=FLASH_ATTN VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 \
  .venv/bin/vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ \
    --max-model-len 64000 --gpu-memory-utilization 0.6 --port 8000
  ```
- **前置一次性設定**：已把 YaRN 寫進該模型 HF 快取的 `config.json`（`rope_scaling={rope_type:yarn,factor:2.0,original_max_position_embeddings:32768}`），patch 腳本 `scratchpad/patch_rope.py`。若重抓模型需重跑。
- 測試腳本：`~/vllm-test/tool_test_openai.py`。
- **踩坑與解法見 [§12]**。

### 4.3 本地素材生成（AI agent 自動產出，非人工手繪）
- **美術（角色 / 場景）**：由 **AI agent 直接程式化操控 Blender**（headless + Python 腳本 `blender_anim2.py`）渲染 3D 可愛 chibi → 2.5D 精靈圖與動畫（走 / 坐 / 講 / 待機 × 6 部門 × 4 變體、方向性貼圖）。**全程由 AI 自動產生，不是人工開軟體繪製。**
- **音樂 / 音效**：由 **AI agent 呼叫 AudioLDM2** 生成辦公室 BGM 與環境音效。

## 7. 資料模型（給接手者可直接開建）

> 以下為 client 端（單檔 HTML5/JS）世界狀態的概念模型；伺服器信任層另以 Java 實作（見 §17）。

```ts
type Dept = '產' | '銷' | '人' | '發' | '財' | '老闆';
type Place = 'desk' | 'meeting' | 'pantry' | 'walking';

interface Character {
  id: string; name: string; dept: Dept; title: string;
  avatar: string;                 
  personality: string[];          // 個性標籤
  traits: { diligence:number; sociability:number; skill:number }; // 0..1
  mood: number; energy: number;   // 0..1
  pos: { x:number; y:number };    // 等角座標
  place: Place;
  currentTaskId?: string;
}

interface Task {
  id: string; title: string; desc: string;
  dept?: Dept; assigneeId?: string;
  status: 'open'|'doing'|'done'|'failed';
  createdBy: 'player'|'system'; progress: number;
}

interface Announcement { id:string; text:string; at:number; }

interface WorldState {
  tick:number; gameTime:string;    // 作息時鐘
  characters: Character[]; tasks: Task[]; announcements: Announcement[];
  metrics: { revenue:number; morale:number; orders:number };
}
```

**角色大腦 prompt 範式**（Node → 本地 LLM）：
> system：你是 {name}，{dept}部門{title}，個性{personality}。你在一間電商公司上班。只能用工具改變狀態；不知道即時資訊就說不知道，不要瞎掰。
> user：現在是 {gameTime}，你在 {place}，心情{mood}精力{energy}。目前任務：{task}。老闆最新公告：{announcement}。請決定你接下來 10 分鐘要做什麼，並說一句符合個性的內心話（≤20字）。回傳 JSON：{action, target, line}。

## 12. 已知踩坑與解法（hard-won，別重踩）

- **vLLM 在 RTX 5090(Blackwell) 上**：
  - 缺 `Python.h` → Triton gcc 編譯失敗。解：`wsl -u root -- apt install -y python3.12-dev`（WSL root 免密碼）。
  - flashinfer 會在執行期用 `nvcc` JIT（本機無 CUDA toolkit）→ 崩。**不要移除 flashinfer**（vLLM 0.32 硬 import 它），改用環境變數 `VLLM_USE_FLASHINFER_SAMPLER=0` + `VLLM_ATTENTION_BACKEND=FLASH_ATTN` 繞過。
  - `--gpu-memory-utilization 0.55`：因 GPU 同時供 Windows 顯示，留緩衝免 OOM。
- **WSL 背景行程陷阱**：`wsl -- bash -c "... &"` 的背景行程會隨連線結束被回收。要常駐請用 Windows 端背景執行（工具的 run_in_background）。
- **`pkill -f` 自殺**：用 `pkill -f 'apt'` 之類時，若自己的命令列也含該字串會把自己 SIGKILL。改用埠精準定位（`fuser -k 8000/tcp` / `ss` 找 PID 殺 pgid）。
- **PowerShell→wsl→bash 多層引號**：巢狀 `"`/JSON 常被吃成 parse error。解：把 python/JSON 寫成檔案再執行，別硬塞 inline。
- **Qwen 會對常識題瞎掰**（如天氣）：用強系統提示「無即時知識、一律查工具、不准瞎掰」可修正（實測從 3/4 → 4/4）。
- **config.yaml 自訂端點**：`model: {default, provider: custom, base_url, api_key, streaming: false}`。

## 14. 遊戲性設計與差異化（已實作）

> 這段是把「一個會自己活著的辦公室」變成**一個有玩頭的遊戲**的設計主軸。核心差異化＝**湧現式敘事 + 人際關係 + 記憶**，三者都靠本地 LLM 才成立，是純腳本遊戲做不到的。

### 定位
一句話：**「你是老闆，但公司是活的。」** 不是放置掛機、也不是數值最佳化，而是看一群有個性的人在你手下相處、摩擦、成長、出事，你用四個權力去影響這個生態。

### 三大支柱
1. **湧現敘事**：營收/訂單是骨架，真正好玩的是人——誰跟誰變好朋友、誰在八卦誰、誰忽然要離職。沒有兩局一樣。
2. **人際關係**：每對員工有關係分數，受個性相容性（BOND/CLASH）與互動歷史影響；好友被解職會讓其他人心情掉。
3. **記憶**：兩層。**公司層**近期事件（招募/解職/公告/完成任務）進入對話 prompt；**個人層**每位員工累積自己的經歷（被加薪/提案被採納/好友離職/當 MVP…），存進存檔、顯示在資訊面板「個人經歷」、並餵進他跟老闆對話與八卦的 prompt，讓他會提起自己的過去。世界因此有連續感、每個人都是一條故事線。

### 核心循環（已實作）
- **P0 經濟核心**：每人 `生產力 = 技能 × 心情 × 精力 × 部門權重`；上班時段累積營收/訂單，技能隨工作成長；每天 18:00 日終結算（營收 − 薪資 = 淨利 → 現金，MVP 表揚）。**張力＝人太多 → 薪資 > 營收 → 虧損**，逼玩家取捨。
- **P1 關係網 + 茶水間八卦**：相容性決定互動是拉近或推遠；後端 `/character/converse` 吃「關係 + 公司事件」生成帶八卦、語氣隨關係的對話（好友同情、死對頭互嗆）。
- **P1 員工主動事件**：員工會依狀態主動向老闆**開口**——加薪（技能高心情好）、請假（精力低）、抱怨（心情差）、提案（心情好技能夠，採納可賺錢）、離職（心情太差，可加薪慰留或放人）。台詞全 LLM 生成，玩家用卡片「採納／否決」回應，各有後果。
- **個人記憶（記憶支柱落地）**：每位員工 `c.memory` 累積帶日期的個人經歷（加薪/請假/抱怨/提案/慰留/交友/鬧翻/完成任務/當 MVP/好友離職…），在上述所有事件點 `pushMem()` 寫入、存進存檔、顯示在資訊面板「個人經歷」、並以 `recentMem()` 餵進 chat／converse 的 prompt（後端 `ChatReq.memory`、`Peer.mem`）。員工跟老闆聊天或跟同事八卦時會自然帶到自己的過去。
- **性別外型 + 辦公室戀情**：角色有性別，**外型一眼可辨**——男性短髮＋長褲、女性長髮＋洋裝＋睫毛（Blender `blender_anim2.py` 加 `gender`，女性變體 v1/v3 重渲，男性 v0/v2 沿用；貼圖以 960 格全域 union bbox 重裁對齊）。姓名、貼圖、性別三者一致（先定性別→取對應名字池→取對應奇偶變體），初始陣容 3 男 3 女均衡。**戀情子系統**：單身異性同事（非總經理）隨相處累積好感 `W.crush`，夠高且關係好 → **告白**（LLM 對白）→ 情投意合就**交往**（頭上 💞、心情加成、偶爾放閃甜言蜜語），否則**被拒**；交往後若心情差/關係惡化可能**分手**；對方離職會自動解除。所有戀愛事件寫進公司動態 + 個人記憶（後端 `/character/romance`：confess/accept/reject/sweet/breakup）。

### 為什麼需要本地 LLM（而非腳本）
支柱 1–3 的質感全來自「每句話都是當下生成、吃得到情境」。腳本化的罐頭台詞會讓湧現敘事崩塌成重複感。本地 LLM 讓這一切零邊際成本、可 7×24、資料不出機。

## 15. 商業化策略（企畫人員觀點，2026-10-30）

| 方案 | 說明 | 商業模式 | 優劣 |
|---|---|---|---|
| **A 自帶算力（建議起步）** | 玩家用自己的 GPU 跑本地模型 | **買斷**（Steam/itch $10–15） | 零伺服器成本、利潤 100%；但受眾＝有顯卡的玩家，小眾。先用來驗證題材、養社群、產病毒內容 |
| **B 雲端小模型** | 官方雲端跑量化 3B–7B | **F2P + 訂閱/IAP** | 受眾最大（手機也能玩）；但有推論成本，需靠訂閱覆蓋。7×24 離線營運＝付費雲端功能 |
| **C 瀏覽器 WebLLM** | 玩家瀏覽器用 WebGPU 跑 | F2P | 零伺服器、觸及廣；模型受限、低階機跑不動 |

**建議路線：A → B。** 先以「自帶算力」買斷版在 itch/Steam 上線養社群，再推雲端 F2P 版擴散。

### 15.2 收入來源（依優先序）
1. **內容／劇本 DLC**：劇情化關卡——「90 天衝上市」「併購危機」「從車庫到獨角獸」；以及電商以外的行業皮（遊戲公司/餐飲/新創）。**賣故事與挑戰**，不碰 AI 收費。
2. **外觀 cosmetics（高毛利、不影響平衡）**：辦公室主題（賽博/和風/聖誕）、家具皮膚包、員工服裝/寵物。引擎已有完整家具系統，加一層換皮即可。
3. **角色訂製（病毒點）**：讓玩家**命名／設計自己的員工**（做成自己的同事、朋友、偶像）→ 高度社群分享。
recurring 收入、剛好用到雲端 LLM。
5. **便利性（謹慎、不 pay-to-win）**：存檔槽、離線加速、額外部門上限。

### 15.3 病毒成長引擎
AI 湧現劇情天生可分享——「我的員工今天談戀愛了」「財務跟研發吵架了」。要做 **一鍵分享精華**（截圖/GIF of drama moments）→ 社群傳播帶自然量，比買量便宜。

### 15.4 不要做
- 按則收 AI 費、核心玩法轉蛋、硬性體力牆、能看不能玩的 demo。這些都會殺死「活著的公司」的魔力。

### 15.5 最小可行商業化（接下來要蓋的）
1. **主題／外觀系統**：辦公室主題 + 可換家具皮膚（沿用現有道具系統加 skin 層）。
2. **軟貨幣商店**：現金已存在 → 開一個商店買外觀；之後再加硬貨幣。
3. **1 個付費劇本**：如「90 天衝上市」當內容付費驗證。
4. **分享功能**：drama 時刻的截圖/GIF 匯出。

### 15.6 Go-to-market 階段
- **A 期**：打磨免費核心，itch/web 以「自帶 GPU」demo 上線，養社群、產病毒 clip。
- **B 期**：Steam 買斷（$10–15）＋劇本 DLC ＋外觀。
- **C 期**：雲端 F2P（手機）＋離線營運訂閱。

### 15.7 三條算力路線並行（2026-10-30 使用者決策）
不鎖單一路線，程式與內容跟「算力位置」解耦（client 只打一個可切換的生成來源）。**三條都做**：
- **A 自帶算力**：連本機 vLLM（現狀）。
- **B 雲端**：連官方雲端端點（換 BACKEND_URL 即可）。
- **C 瀏覽器 WebLLM（戰略最高）**：模型跑在玩家瀏覽器（WebGPU，如 Qwen2.5-1.5B/Llama-3.2-3B，首次下載快取）。**零伺服器成本 + 免玩家自架 + 可大規模發行**。做法：client 增加「瀏覽器生成」路徑，複用同一套 prompt 組裝，產出走 WebLLM 而非 fetch 後端。三者以設定切換，優先序：有後端用後端，否則用瀏覽器 WebLLM，再否則內建保底。

## 16. 獲利方式（定案，2026-10-30・以玩家渴望為核心）

> **§15 講的是「成本結構」（給投資人）；§16 講的是「玩家為什麼想付錢」（給遊戲）。後者才是關鍵——沒有渴望，任何定價都是空的。**

### 16.1 核心診斷
玩家不會為「系統」付錢，只會為「在乎的東西」付錢。目前的失敗點：①代管預設開＝玩家在看戲、沒有擁有感；②角色是「隨機活的」但不是「我的」，可替換故無依附；③沒有跨天懸念故無回訪。**變現軌道（商店/劇本/分享）都鋪好了，缺的是製造渴望的情感引擎。**

### 16.2 兩個情感對象 → 兩台變現引擎
- **對員工的愛** → 收集、挽留、打扮、延續其故事。
- **對公司的愛** → 公司是「我建的、有歷史、有排名、會倒」的東西。**會倒才有賭注**，賭注＝「不想失去」＝儲值引擎。

### 16.3 公式
**免費玩到飽（隨機員工＋玩家端算力＝零成本）→ 玩家養出感情 → 付費點全是「深化／表達／收集／延續」那份感情。** 永不賣 AI、不賣戰力、不搞「付錢才不會失去朋友」。

### 16.4 人才庫系統（招募／解職的核心樞紐）
招募與解職進出一個**人才庫**，三來源：
1. **🎓 校友庫**：被解職／自主離職／被挖角的人全進校友庫**不消失**，可**花現金再招回**（後悔驅動消費）。
2. **🌟 夢想人才市場**：輪替的精品角色清單（獨特人格/背景/立繪，LLM 演活），**指定購買非抽卡**（道德、好過審、玩家信任）。這是「活靈魂收集」，比 gacha 強。
3. **🧑‍💼 一般招募**：免費隨機員工。

### 16.5 儲值管道（錢進來的地方）
premium 貨幣「💎 資本／注資」：真錢 → 資本 → 換 公司現金／夢想人才／外觀／羈絆深化／季票。**現金見底又有限時夢想人才＝最強轉化時刻。**

### 16.6 虧錢壓力曲線（漸進，非猝死）
①現金低→警告、士氣跌、暫停招募 → ②轉負→有人提離職（進校友庫）→ ③深負 N 天→逼近破產清算。懸崖邊給兩條路：**①儲值注資救公司（公司情感變現）／②讓它倒，進 recycle。**

### 16.7 破產 Recycle（重經營）— 整套靈魂，防作惡關鍵
**公司會倒，但捨不得的東西一樣都不奪走。** 破產時保留：✅人才庫/校友庫（心愛的人回名冊，下一間公司帶著東山再起）、✅所有付費特聘靈魂（信任底線）、✅成就/排行榜/大事記、✅外觀。**只重置當前公司的現金與營運進度**＝開新公司（roguelike 新一輪）但帶著收集與傳奇長大。一招解四題：公司真的會死（有賭注撐轉化）、絕不作惡（付費/心愛永不永久失去）、跨局 meta 成長（收集越玩越厚）、正是要的 recycle。

### 16.8 轉化時刻總表
| 時刻 | 掏錢理由 | 情感來源 |
|---|---|---|
| 招募夢想人才 | 「想要這個獨一無二的靈魂」 | 收集 |
| 招回後悔開除/被挖走的人 | 「想把他請回來」 | 後悔、依附 |
| 懸崖邊救公司 | 「不想失去我建的公司」 | 公司情感、損失趨避 |
| 外觀/羈絆/季票 | 「讓他更好看、故事傳下去」 | 表達、延續 |

### 16.9 不作惡三底線（長線關鍵）
1. 免費玩家永遠能靠 recycle 重生，不被 paywall 卡死。
2. 付費與心愛的人永不永久奪走——儲值＝加速/情感/收集，非「不付就毀滅」。
3. 夢想人才賣人格與獨特**非碾壓戰力**——維持「收集」而非 pay-to-win。

### 16.10 開發順序
1. ✅ **最愛角色依附迴圈（已實作 2026-10-30）**：羈絆值 `bond`(聊天/答應請求/慰留加深，疏於互動退)、⭐最愛(單選、頭上標記)、5 條個人故事線 `ARCS`(隨羈絆跨門檻推進 beat→達成夢想 payoff)。inspect 面板有羈絆條+夢想進度+最愛鈕。這是讓下面變現有意義的情感引擎。
2. **人才庫原型**（校友庫＋夢想市場＋再招回，先用遊戲現金跑通「失去→想念→招回/收集」迴圈）。
3. **破產 recycle**（含跨局保留）。
4. **儲值**（真錢→資本）疊上。
5. 外觀/羈絆/季票/劇本加乘。

## §17 會員系統與雲端架構（2026-10-30）

### 17.1 核心原則：算力留本地，信任上雲端
一旦要收真錢，錢包就不能放 localStorage（F12 一行 `W.gems=99999` 就破功）。
身分／錢包／已購項目／記錄／排行必須由**伺服器**當權威。但這不違反「不對 AI 收費」哲學——
LLM 推論與遊戲模擬仍留本地（零成本），只有「信任層」上伺服器。

| 留本地（胖客戶端，零成本） | 上伺服器（瘦信任層） |
|---|---|
| LLM 推論、遊戲模擬、NPC、辦公室狀態 | 帳號身分／登入 |
| 所有玩法運算 | **伺服器權威錢包**（資本儲值、寶石）|
| | 已購權益（外觀／夢想員工／劇本）|
| | 經營史記錄（破產／成就／傳承）|
| | 排行榜、跨裝置存檔 |

### 17.2 基礎設施（全 local）
- **Rancher Desktop k8s 叢集**（k3s）＝「本地的雲端」。namespace `yocat`。
- **PostgreSQL 16**（Deployment + PVC local-path 持久化 + NodePort 30432）＝雲端 DB。
- 後端：**Java 21 · Spring Boot · Spring Modulith**（`java-backend/apps/api`，7 個 BC、Clean Architecture），部署於 k8s，連 in-cluster PostgreSQL。（早期 Node 原型 `server/` 未採用）
- manifests：`docs/req/postgres.yaml` + `java-backend/k8s/overlays/local/`（Kustomize）；schema：**schema-per-BC** Flyway 遷移 `java-backend/migrations/*.sql`。
- 整條流程都在本機跑完，符合 local-first 要求。

### 17.3 資料模型（schema-per-BC，7 個 BC）
member（accounts/sessions…）、wallet（wallets/wallet_ledger…）、deposit、entitlement、record、leaderboard、game_save，各 BC 獨立 schema（另有 platform / modulith 橫切 schema）。

### 17.4 API（伺服器權威）
- `/auth/register`、`/auth/login`、`/auth/logout`、`/auth/me`（scrypt 雜湊、session token）
- `/wallet/topup`（假付費，走 ledger）、`/wallet/spend`（交易扣款，餘額不足回 402）
- `/entitlements`、`/entitlements/buy`（原子：扣款+授予，重複回 409）
- `/save`（GET/PUT，跨裝置）、`/records`（破產/成就/傳承）、`/leaderboard`（公開 Top N）

### 17.5 玩家體驗流程
啟動 → 帳號選擇（建立辦公室／登入／訪客試玩）→ 我的辦公室（存檔、錢包、記錄都掛此帳號）。
訪客可玩，要收費／上榜／跨裝置才要求註冊（降低進入門檻，符合 F2P 哲學）。
破產不是刪號，是這個帳號經營史上的一筆記錄。

### 17.6 開發進度
- ✅ 基礎設施（k8s Postgres + schema）
- ✅ 後端 API 全套（Java Spring Modulith；含 JUnit / BDD / 合約 / E2E 測試套件）
- ✅ 客戶端整合（帳號畫面、API client、錢包/記錄/存檔/排行上雲）全綠
- 之後：真金流 SDK（Phase B，接口已預留）
